# 담당 기능 발표자료 초안

## 문서 목적

이 문서는 팀 발표자료에 병합하기 전, 개인 담당 기능에 해당하는 슬라이드를 정리한 초안이다.
다른 데스크탑에서 작업할 때 이 파일과 저장소의 현재 코드를 함께 확인해 PPT 제작을 이어간다.

## 담당 범위

- Supabase Auth 기반 사용자 로그인·회원가입
- 사용자 마이페이지와 프로필 관리
- 청약 공고 검색 및 선택
- 청약 공고 주변 생활권 분석
- Kakao Local API 기반 주소 좌표 변환 및 주변 시설 조회
- PyDeck 기반 지도 시각화
- 위 기능과 관련된 백엔드 API 및 테스트

> 실시간 로그 대시보드와 로그 이력 조회 기능은 담당 범위가 아니므로 개인 발표자료에서 제외한다.

## 발표 방향

- 예상 발표 시간: 약 4분
- 예상 슬라이드 수: 7장
- 핵심 메시지: 사용자가 안전하게 가입하고 자신의 정보를 관리하며, 청약 공고의 가격 조건뿐 아니라 주변 생활환경까지 함께 판단할 수 있도록 구현했다.
- 팀 전체 기능을 반복해서 설명하기보다 개인 담당 기능의 문제, 설계, 구현 결과를 중심으로 설명한다.

## 슬라이드 1. 표지

### 제목

공공임대·분양 청약 통합 안내 서비스

### 부제

사용자 인증과 주변 생활권 분석

### 하단 표기

- 담당: 로그인·회원가입, 마이페이지, 위치 기반 분석
- 발표자 이름은 최종 PPT 병합 시 입력

### 디자인 메모

- 표지는 텍스트를 최소화한다.
- 서비스 메인 화면 또는 생활권 지도 화면을 대표 이미지로 사용할 수 있다.

## 슬라이드 2. 계획서 — 해결하려는 사용자 문제

### 제목

청약 조건뿐 아니라 생활환경까지 한 화면에서 판단합니다

### 본문

청약 서비스 사용자가 겪는 다음 문제를 해결하는 것을 목표로 했다.

1. 사용자가 안전하게 가입하고 로그인할 수 있어야 한다.
2. 연락처와 관심 분야 등 개인 정보를 직접 관리할 수 있어야 한다.
3. 청약 공고 주변의 교통·생활·의료 시설을 함께 확인할 수 있어야 한다.

### 담당 기능

- Supabase Auth 기반 인증
- 사용자 프로필 관리
- 등록된 청약 공고 검색 및 선택
- Kakao Local API 기반 주변 시설 분석
- PyDeck 지도 시각화

### 추천 시각 요소

`회원가입 → 공고 선택 → 주변 시설 확인` 순서의 간단한 사용자 흐름을 배치한다.

## 슬라이드 3. 화면설계서 — 사용자 이용 흐름

### 제목

가입부터 생활권 분석까지 끊김 없는 사용자 흐름을 구성했습니다

### 화면 흐름

```text
회원가입
  ↓
로그인
  ↓
청약 공고 검색·선택
  ↓
공고 주소 좌표 변환
  ↓
주변 지하철·마트·병원 조회
  ↓
지도와 예상 도보시간 확인
```

### 주요 화면

- 회원가입: 약관 동의 후 사용자 정보 입력
- 로그인: 이메일과 비밀번호를 이용한 Supabase 인증
- 마이페이지: 프로필과 비밀번호 수정
- 생활권 분석: 공고 검색, 검색 반경 선택, 지도 결과 확인

### PPT 제작 시 필요한 캡처

- 회원가입 화면
- 마이페이지 화면
- 생활권 분석 검색 화면
- 주변 시설이 표시된 지도 결과 화면

실제 실행 화면 캡처 3~4장을 사용하는 것을 권장한다.

## 슬라이드 4. 데이터베이스 설계서 — 인증과 프로필 분리

### 제목

인증은 Supabase에 맡기고 서비스용 사용자 정보는 별도로 관리했습니다

### 구조

```text
Supabase auth.users
        │ 1:1
        ▼
profiles
├─ id: UUID
├─ nickname
├─ phone
├─ birth_date
├─ interests: JSONB
└─ created_at
```

### 핵심 설계

- 비밀번호는 애플리케이션의 프로필 테이블에 저장하지 않는다.
- `auth.users`가 이메일, 비밀번호, 인증 세션을 관리한다.
- `profiles`가 닉네임, 연락처, 생년월일, 관심 분야를 관리한다.
- 회원 생성 시 데이터베이스 트리거로 프로필 행을 자동 생성한다.
- 사용자 UUID를 기준으로 인증 사용자와 프로필을 연결한다.
- 생활권 정보는 외부 API에서 실시간으로 조회하며 현재는 별도 테이블에 저장하지 않는다.

### 관련 파일

- `BE/sql/schema.sql`
- `BE/sql/profiles.sql`

## 슬라이드 5. API 명세서 — 프로필과 위치 분석

### 제목

프로필 API와 위치 API를 통해 사용자 화면을 연결했습니다

| Method | Endpoint | 역할 |
| --- | --- | --- |
| GET | `/profiles/{user_id}` | 사용자 프로필 조회 |
| PUT | `/profiles/{user_id}` | 닉네임, 연락처, 관심 분야 등 프로필 수정 |
| GET | `/location/geocode` | 공고 주소를 위도·경도 좌표로 변환 |
| GET | `/location/nearby-subways` | 지정 반경 내 지하철역 조회 |
| GET | `/location/nearby-facilities` | 마트·병원 등 주변 시설 조회 |

### 구현 특징

- 회원가입과 로그인은 프런트엔드에서 Supabase Auth를 직접 호출한다.
- 위치 API는 Kakao Local API 응답을 서비스 화면에서 사용하기 쉬운 형태로 가공한다.
- 주소 검색이 실패하면 키워드 검색을 이용해 좌표 탐색을 보완한다.
- 외부 API 오류와 검색 결과가 없는 상태를 구분해 처리한다.

### 관련 파일

- `BE/app/routers/profile_router.py`
- `BE/app/routers/location_router.py`
- `FE_User/clients/`

## 슬라이드 6. README — 실행 구성과 설정

### 제목

사용자 기능은 Streamlit, FastAPI, Supabase, Kakao Local API로 동작합니다

### 실행 구조

```text
FE_User (Streamlit)
      │
      ├── Supabase Auth
      │
      └── FastAPI
             │
             ├── Supabase PostgreSQL
             └── Kakao Local API
```

### 실행 순서

1. Supabase 인증과 데이터베이스 테이블을 설정한다.
2. 백엔드 환경변수를 설정하고 FastAPI 서버를 실행한다.
3. 사용자 프런트엔드 환경변수를 설정한다.
4. Streamlit 사용자 앱을 실행한다.
5. 회원가입과 로그인 후 생활권 분석 화면을 확인한다.

### README에 추가로 보강할 내용

- `KAKAO_REST_API_KEY` 설정 방법
- 생활권 분석 기능의 실행 예시
- 주요 사용자 화면 이미지
- 프런트엔드에는 Supabase anon key만 사용한다는 보안 안내
- Service Role Key를 프런트엔드에 노출하지 않는다는 주의사항

### 관련 파일

- `README.md`
- `BE/.env.example`
- `FE_User/.env.example`

## 슬라이드 7. 구현 결과와 개선 방향

### 제목

사용자는 청약 공고와 주변 생활환경을 함께 비교할 수 있습니다

### 구현 결과

- 인증 정보를 애플리케이션에서 직접 저장하지 않는 회원 시스템 구현
- 사용자 추가정보와 비밀번호 수정 기능 구현
- 등록된 청약 공고를 대상으로 한 검색과 선택 기능 구현
- 지하철, 마트, 병원 등 주변 시설의 지도 표시
- 직선거리를 바탕으로 한 예상 도보시간 제공
- 위치 API와 공고 검색 로직 테스트

### 현재 한계

- 예상 도보시간은 실제 보행 경로가 아닌 직선거리 기반 추정값이다.
- 외부 위치 API 응답 속도와 호출 제한의 영향을 받을 수 있다.
- 같은 주소와 시설을 반복해서 조회할 때도 외부 API를 다시 호출한다.

### 향후 개선

- 주소 좌표와 주변 시설 검색 결과 캐싱
- 실제 보행 경로 API 연동
- 여러 청약 공고의 생활권 비교 기능
- Access Token을 이용한 백엔드 사용자 검증 강화

### 마무리 발표 문장

> 사용자 인증과 프로필 관리에 더해, 청약 공고의 가격 정보만으로는 알기 어려운 생활환경을 지도에서 함께 판단할 수 있도록 구현했습니다.

## 발표 대본 초안

### 0:00~0:30 — 담당 기능 소개

저는 Supabase Auth를 이용한 사용자 로그인·회원가입과 마이페이지 기능을 담당했습니다. 추가로 청약에서는 가격뿐 아니라 생활권도 중요하다고 생각해, 공고 주변 시설을 지도에서 확인하는 생활권 분석 기능을 구현했습니다.

### 0:30~1:20 — 인증과 프로필

로그인과 회원가입은 비밀번호를 직접 저장하지 않고 Supabase Auth에 인증을 맡겼습니다. 로그인에 성공하면 사용자 정보와 인증 토큰을 세션에서 관리합니다. 회원가입에서는 약관 동의와 입력값을 검증하고, 닉네임과 연락처 같은 추가정보를 Supabase에 전달합니다. 마이페이지에서는 프로필과 비밀번호를 수정할 수 있습니다.

### 1:20~3:20 — 생활권 분석

생활권 분석에서는 먼저 서비스에 등록된 청약 공고를 검색하고 하나를 선택합니다. 선택한 공고의 주소를 Kakao Local API로 좌표로 변환한 뒤, 지정한 반경 안의 지하철역, 마트, 병원을 조회합니다. 검색 결과는 PyDeck 지도에 표시하며, 시설까지의 직선거리를 이용해 예상 도보시간도 함께 제공합니다. 주소 검색이 실패하면 키워드 검색으로 한 번 더 좌표를 찾도록 보완했습니다.

### 3:20~4:00 — 결과와 개선 방향

이 기능을 통해 사용자는 청약 가격과 일정뿐 아니라 실제 생활 편의성도 함께 비교할 수 있습니다. 현재 도보시간은 직선거리 기반 추정값이므로, 이후 실제 경로 API와 좌표 캐시를 추가하면 정확도와 응답 속도를 개선할 수 있습니다.

## 다른 데스크탑에서 이어서 작업하기

### Git으로 동기화하는 경우

1. 이 파일을 포함한 변경사항을 개인 브랜치에 커밋한다.
2. 원격 저장소에 push한다.
3. 다른 데스크탑에서 같은 브랜치를 checkout한다.
4. `git pull`로 최신 변경사항을 내려받는다.
5. `docs/PRESENTATION_DRAFT.md`를 열어 PPT 제작을 계속한다.

### PPT 제작 전 확인사항

- 발표자 이름과 팀명이 확정되었는지 확인
- 개인 발표시간 확인
- 팀 공통 PPT의 비율, 색상, 글꼴 확인
- 실제 사용자 화면 캡처 준비
- 팀원 자료와 겹치는 프로젝트 소개 내용 축소
- API 경로와 화면이 최종 코드와 일치하는지 재확인
