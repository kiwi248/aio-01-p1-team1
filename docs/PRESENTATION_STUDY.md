# 담당 기능 발표 학습 정리

## 1. 담당 기능 요약

담당한 핵심 기능은 다음 두 가지입니다.

1. Supabase Auth 기반 사용자 로그인·회원가입과 마이페이지
2. Kakao Local API와 PyDeck을 활용한 청약 공고 생활권 분석

사용기술(streamlit,fastAPI,supabase,kakao rest API,pydeck)

발표 시작 문장:

> 저는 사용자 프론트엔드의 로그인·회원가입과 마이페이지 기능을 담당했습니다. 추가로 청약 공고 주변의 지하철역, 마트, 병원을 지도에서 확인할 수 있는 생활권 분석 기능을 구현했습니다.

## 2. 4분 발표 구성

### 0:00~0:30 담당 기능 소개

> 저는 Supabase Auth를 이용한 사용자 로그인·회원가입과 마이페이지 기능을 담당했습니다. 추가로 청약에서는 가격뿐 아니라 생활권도 중요하다고 생각해, 공고 주변 시설을 지도에서 확인하는 생활권 분석 기능을 구현했습니다.

### 0:30~1:30 로그인·회원가입과 마이페이지

> 로그인과 회원가입은 비밀번호를 직접 저장하지 않고 Supabase Auth에 인증을 맡겼습니다. 로그인에 성공하면 사용자 ID와 인증 토큰을 Streamlit 세션에 저장합니다. 회원가입에서는 약관 동의, 비밀번호 확인, 전화번호, 생년월일과 관심 분야를 검증하고, 닉네임과 연락처 같은 추가정보도 Supabase에 전달했습니다. 마이페이지에서는 프로필과 비밀번호를 수정할 수 있으며, 휴대번호 중복도 백엔드에서 검사합니다.

### 1:30~3:30 생활권 분석

> 생활권 분석에서는 임의의 장소가 아니라 서비스에 등록된 청약 공고만 검색할 수 있도록 했습니다. 공고명, 주택명, 지역과 상세주소를 검색 대상으로 사용하고, 공백과 문자 표기를 정규화해 검색 정확도를 높였습니다.
>
> 선택한 공고의 상세주소는 Kakao Local API를 이용해 위도와 경도로 변환합니다. 주소 검색 결과가 없으면 장소명으로 다시 검색하고, 두 검색 모두 실패하면 404 오류를 반환합니다.
>
> 변환된 좌표를 중심으로 지하철역, 마트, 병원을 검색합니다. Kakao 카테고리 코드 SW8, MT1, HP8을 사용했으며, 검색된 거리로 예상 도보시간을 계산했습니다.
>
> 결과는 PyDeck 지도에 표시했습니다. 공고와 시설을 서로 다른 아이콘으로 구분하고, 연결선과 거리, 예상 도보시간을 함께 표시했습니다.

### 3:30~4:00 마무리

> 이 기능을 구현하면서 사용자 인증과 세션 관리, 외부 API 응답 처리, 지도 시각화를 학습했습니다. 생활권 분석을 통해 사용자가 청약 가격뿐 아니라 실제 주변 생활환경도 함께 비교할 수 있도록 했습니다. 향후에는 실제 도보 길찾기 API와 좌표 캐시를 적용해 정확도와 효율을 개선할 수 있습니다.

## 3. Supabase Auth 학습

### Supabase Auth란?

회원가입과 로그인을 직접 구현하지 않고 Supabase의 인증 기능에 맡기는 방식입니다.

```text
사용자가 이메일·비밀번호 입력
→ 프론트엔드가 Supabase Auth에 전달
→ Supabase가 가입 또는 로그인 처리
→ 성공하면 사용자 정보와 인증 토큰 반환
```

Supabase가 비밀번호 암호화, 사용자 확인, 로그인 세션과 토큰 발급을 담당합니다.

### Access Token

```python
st.session_state.access_token = result.session.access_token
```

현재 사용자가 정상적으로 로그인했다는 것을 증명하는 유효기간이 짧은 출입증입니다. 로그인이 필요한 백엔드 API를 호출할 때 전달합니다.

```text
Authorization: Bearer 액세스토큰
```

### Refresh Token

```python
st.session_state.refresh_token = result.session.refresh_token
```

Access Token이 만료됐을 때 새로운 Access Token을 발급받는 데 사용하는 갱신증입니다.

```text
Access Token 만료
→ Refresh Token으로 갱신 요청
→ 새 Access Token 발급
→ 로그인 상태 유지
```

### 왜 `st.session_state`에 저장하나?

Streamlit 화면은 사용자 입력이 발생할 때 코드를 다시 실행할 수 있습니다. 같은 사용자 세션에서 로그인 정보와 토큰을 계속 사용하기 위해 `st.session_state`에 저장합니다.

### 회원가입 메타데이터란?

Swagger 태그가 아니라 사용자 계정에 덧붙이는 추가정보입니다.

```text
인증 핵심 정보: 이메일, 비밀번호
사용자 추가정보: 닉네임, 전화번호, 생년월일, 관심 분야
```

```python
"options": {
    "data": {
        "nickname": nickname,
        "phone": phone,
        "birth_date": birth_date,
        "interests": interests,
    }
}
```

발표에서는 `메타데이터` 대신 `사용자 추가정보`라고 설명해도 됩니다.

## 4. 공고 검색 학습

생활권 분석은 Kakao에서 임의 장소를 먼저 찾지 않습니다. 우리 서비스에 등록된 청약 공고 안에서 검색합니다.

```text
검색어 입력
→ 백엔드에서 등록 공고 목록 조회
→ 공고 정보를 검색용 문자열로 합침
→ 검색어와 공고 문자의 표기를 정리
→ 검색어가 포함된 공고만 반환
```

### 등록 공고 가져오기

```python
listing_response = get_listings()
all_listings = listing_response.get("data") or []
```

### 검색 대상 필드

```python
values = [
    listing.get("title"),
    listing.get("housing_name"),
    listing.get("location"),
    listing.get("detail_address"),
]
```

- 공고명
- 주택명
- 지역
- 상세주소

### 검색어 정규화

```python
normalized = unicodedata.normalize(
    "NFKC",
    str(value or ""),
).casefold()

return "".join(normalized.split())
```

- 값이 없어도 빈 문자열로 처리
- 비슷한 Unicode 문자 표기 통일
- 영문 대소문자 통일
- 공백 제거

### 포함 여부 확인

```python
if normalized_query in listing_search_text(listing):
    # 검색 결과에 공고 추가
```

예시:

```text
검색어: 장기전세
공고 문자열: 중랑구장기전세서울중랑구면목로300
결과: 포함되므로 검색 결과에 추가
```

발표 문장:

> 백엔드에서 등록된 공고를 가져와 공고명, 주택명, 지역, 상세주소를 검색 대상으로 만들었습니다. 공백과 영문 대소문자 등을 정리한 뒤 검색어가 포함된 공고만 보여줍니다.

## 5. Kakao Local API 학습

현재 프로젝트에서는 Kakao Local API를 세 가지 용도로 사용합니다.

### 1. 주소를 좌표로 변환

```text
공고 상세주소 → 위도·경도
```

### 2. 주소 검색 실패 시 키워드 검색

```text
주소 검색 실패
→ 장소명 키워드 검색
→ 결과도 없으면 404
```

### 3. 좌표 주변 시설 검색

```text
SW8 → 지하철역
MT1 → 대형마트
HP8 → 병원
```

전체 흐름:

```text
공고 선택
→ 상세주소를 좌표로 변환
→ 좌표 주변 지하철역·마트·병원 검색
→ 거리와 예상 도보시간 계산
→ 지도에 표시
```

### 추후 추가할 기능: 좌표 캐시

아래 내용은 현재 구현된 기능이 아니라 추후 추가할 예정인 기능입니다.

기존 청약공고 데이터는 그대로 유지하면서 위도·경도를 선택적으로 저장하고, 잘못된 좌표가 DB에 들어가는 것을 방지해 지도 표시와 좌표 캐시에 활용하려는 SQL입니다.

좌표 캐시로 연결하면 최초 조회 시에만 공고 주소를 Kakao Local API로 변환하고, 결과를 이 컬럼에 저장합니다. 다음 조회부터는 저장된 좌표를 사용하므로 API 호출 횟수와 응답 시간을 줄일 수 있습니다.

## 6. 예상 도보시간 학습

현재 결과는 실제 길찾기 시간이 아니라 참고용 추정치입니다.

```text
예상 도보시간 = 올림(직선거리 × 1.25 ÷ 75)
```

- `1.25`: 직선으로 이동할 수 없는 우회 거리를 간단히 반영한 보정값
- `75m/분`: 평균 보행속도
- `올림`: 소수점 시간을 분 단위로 올림

300m 예시:

```text
300 × 1.25 ÷ 75 = 5분
```

질문 답변:

> Kakao 시설 검색 결과는 실제 보행 경로를 제공하지 않기 때문에 직선거리에 보정값과 평균 보행속도를 적용했습니다. 정확한 길찾기 시간이 아니라 시설 비교를 위한 참고용 예상시간입니다.

실제 도보 경로 API는 무료 쿼터가 있지만 호출량이 제한되고 추가 구현이 필요합니다. 프로젝트 일정과 MVP 범위를 고려해 추정 방식으로 구현했습니다.

## 7. 지도 기술 학습

### PyDeck

파이썬 기본 내장 기능이 아니라 별도로 설치하는 지도 시각화 라이브러리입니다.

```powershell
pip install pydeck
```

프로젝트에서 사용한 계층:

- `IconLayer`: 공고와 시설 아이콘
- `LineLayer`: 공고와 시설 연결선
- `TextLayer`: 시설명, 거리와 예상 도보시간
- `Tooltip`: 마우스를 올렸을 때 상세정보

Streamlit 출력:

```python
st.pydeck_chart(location_deck)
```

### CARTO와 OpenStreetMap

파이썬 라이브러리가 아닙니다.

- OpenStreetMap: 도로, 건물, 지명 등의 공개 지도 데이터
- CARTO: 지도 배경의 타일과 디자인 스타일 제공
- PyDeck: 배경 지도 위에 공고와 시설을 시각화
- Streamlit: 완성된 지도를 웹 화면에 출력

정확한 발표 표현:

> Kakao Local API로 주소와 주변 시설을 검색하고, OpenStreetMap 기반 CARTO 배경 지도 위에 PyDeck으로 결과를 시각화했습니다.

피해야 할 표현:

> Kakao Map으로 지도를 만들었습니다.

## 8. 예상 질문과 답변

### 왜 Supabase Auth를 사용했나요?

> 비밀번호 암호화, 사용자 인증과 토큰 발급을 직접 구현할 때 발생할 수 있는 보안 위험을 줄이고 서비스 기능 개발에 집중하기 위해 사용했습니다.

### Access Token과 Refresh Token의 차이는 무엇인가요?

> Access Token은 로그인 사용자를 증명하는 단기 출입증이고, Refresh Token은 만료된 Access Token을 갱신하는 데 사용하는 토큰입니다.

### 프론트엔드에 Supabase 키를 넣어도 되나요?

> 프론트엔드에는 공개용 anon key만 사용합니다. 관리자 권한이 있는 service role key는 절대 넣지 않습니다.

### 사용자 메타데이터는 Swagger 태그인가요?

> 아닙니다. 회원가입 메타데이터는 닉네임과 전화번호처럼 사용자 계정에 함께 저장하는 추가정보입니다. Swagger 태그는 API 문서를 기능별로 분류하는 이름입니다.

### 왜 등록된 공고만 검색하나요?

> 청약 공고의 생활권을 분석하는 서비스이기 때문입니다. 임의 장소를 허용하면 청약정보와 관계없는 결과가 나올 수 있어 서비스에 등록된 공고만 선택하도록 제한했습니다.

### Kakao Local API는 어디에 사용했나요?

> 공고 상세주소를 좌표로 변환하고, 주소 검색 실패 시 장소명으로 재검색하며, 해당 좌표 주변의 지하철역·마트·병원을 찾는 데 사용했습니다.

### 예상 도보시간은 정확한가요?

> 실제 경로 시간이 아니라 직선거리와 평균 보행속도로 계산한 참고용 추정치입니다.

### 실제 길찾기 API는 유료인가요?

> 무료 쿼터가 있지만 호출량이 제한되어 있고, 무료 한도 초과 후 유료 사용을 적용하면 비용이 발생할 수 있습니다.

### PyDeck과 Kakao Map의 차이는 무엇인가요?

> Kakao Local API는 위치 데이터를 검색하고, PyDeck은 검색 결과를 지도 위에 시각화합니다. 배경 지도에는 OpenStreetMap 기반 CARTO 스타일을 사용했습니다.

### API 오류는 어떻게 처리했나요?

> API 키 누락, 네트워크 오류, 검색 결과 없음과 응답 형식 오류를 구분해 HTTP 상태 코드와 사용자 안내 문구를 반환했습니다.

### 테스트는 어떻게 했나요?

> 실제 Kakao API를 호출하지 않도록 Mock을 사용해 주소 검색, 키워드 재검색, 404 응답, 시설 조회와 도보시간 계산을 검증했습니다.

### 현재 기능의 한계는 무엇인가요?

> 실제 보행 경로를 반영하지 못하고, 같은 공고를 분석할 때 주소를 다시 좌표로 변환할 수 있다는 점입니다.

### 다음에 개선한다면 무엇을 추가하나요?

> 실제 도보 경로 API와 좌표 캐시를 적용해 시간의 정확도를 높이고 반복적인 API 호출을 줄이고 싶습니다.

### 본인이 구현한 범위는 어디까지인가요?

> 로그인·회원가입과 마이페이지를 담당했고, 생활권 분석의 백엔드 위치 API, 프론트엔드 공고 검색, 지도 시각화와 테스트를 구현했습니다.

## 9. 발표 전 암기할 핵심 문장

1. Supabase Auth에 인증을 맡겨 비밀번호를 직접 저장하지 않았습니다.
2. Access Token은 사용자 인증용이고, Refresh Token은 인증 갱신용입니다.
3. 생활권 분석은 서비스에 등록된 청약 공고만 검색합니다.
4. Kakao Local API로 주소 좌표 변환과 주변 시설 검색을 수행합니다.
5. 예상 도보시간은 실제 경로가 아닌 직선거리 기반 참고용 추정치입니다.
